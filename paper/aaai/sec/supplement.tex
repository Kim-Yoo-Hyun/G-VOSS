\subsection{Estimator Architecture and Optimization}
RelCompat3D-Linear fits one logistic head for each evaluated relation family. Numeric features use means and standard deviations estimated from the training split.
Missing values use the corresponding training mean. Inputs are predicate indicators $T$, predicate-independent ordered-pair measurements $G$, and the two signed-height interactions defined in the main paper. The relation-family label selects the head and is not an input feature. The source relation score, source rank, predictor identity, and object class are excluded. Relation-preserving augmentation keeps the proximity predicate fixed under endpoint swap and applies the inverse predicate after a vertical-order endpoint swap. Training applies the margin loss from the main paper to linked positive--counterfactual pairs. Support/contact receives the pairwise loss and uses only the identity transformation.

\paragraph{Geometric feature specification.}
Table~\ref{tab:geometry-features} defines the 17 measurements in \(G\). For endpoint \(j\in\{s,o\}\), let \(c_j=(x_j,y_j,z_j)\) be the OBB center and \(b_j\) and \(t_j\) its lower and upper vertical bounds. We set \(h_j=t_j-b_j\), and \(d_j^{3D}\) and \(d_j^{XY}\) denote the diagonals of its 3D and projected XY bounds.
Let \(A_j\) denote the area of the projected bounds and \(I_{XY}\) their intersection area. All distance and height measurements are in meters. Normalized and overlap measurements are dimensionless.

RelCompat3D-MLP fits one shared multilayer perceptron (MLP) with a single two-unit ReLU hidden layer and a predicate-linear skip connection. Its 29 inputs include relation-family and predicate indicators, the same 17 geometric measurements, the two signed-height interactions, and the sum of the directional overlap ratios. Because parameters are shared across families, the relation-family indicator varies across inputs. The estimator has 69 parameters and excludes the source relation score and predictor identity.

The 60,208 training rows yield 33,961 linked pairs, and relation-preserving augmentation produces 86,032 optimization rows for both estimators. Linear uses 800 deterministic full-batch gradient descent steps at learning rate 0.2. MLP uses 120 full-batch Adam steps at learning rate 0.02. Both use the same pairwise weight, margin, and $\ell_2$ coefficient. The three linear family models contain 21--23 parameters. Each reported condition is fitted once with a pre-specified seed. The paired intervals quantify scan resampling rather than retraining variability.

\subsection{Formal Properties}

\begin{proposition}[Exact transformation consistency]
Let a finite transformation group $H_a$ act on both the predicate and geometry of an ordered pair, and define $C_a^{\rm tr}(x)=|H_a|^{-1}\sum_{g\in H_a}C_a(gx)$. Then $C_a^{\rm tr}(hx)=C_a^{\rm tr}(x)$ for every $h\in H_a$.
\end{proposition}

\paragraph{Proof.}
For any $h\in H_a$,
\(
C_a^{\rm tr}(hx)=|H_a|^{-1}\sum_{g\in H_a}C_a(ghx)
\).
Right multiplication by $h$ permutes the elements of the finite group, so re-indexing $g'=gh$ gives $C_a^{\rm tr}(hx)=C_a^{\rm tr}(x)$. The proximity and vertical-order transformations yield the identities in the main paper. For support/contact, the transformation set contains only the identity.

\paragraph{Family-sequence preservation.}
For each family $a$, the algorithm constructs the ordered list $\pi_a$ defined in the main paper. At position $j$, it selects the next unselected candidate from $\pi_{a_j}$. The output relation-family sequence is therefore exactly $(a_1,\ldots,a_n)$. The support/contact list follows the source ranking, so the first $K$ positions contain exactly the same ordered support/contact subsequence as the source prefix. Therefore the support/contact selections and their order are identical at every reported $K$.

\paragraph{Prefix utility optimality.}
Fix a prefix length $K$, and let $n_a(K)$ be the number of positions assigned to family $a$ in the source prefix. Every feasible ranking that preserves these family counts must select $n_a(K)$ candidates from each family. Because each re-ranked $\pi_a$ is sorted by $u_i$, each estimator selects the $n_a(K)$ highest-scoring candidates in that family. Replacing one of these candidates with a lower-scoring candidate from the same family would reduce the summed score of the prefix. The support/contact subsequence is fixed, so it does not affect this comparison.

\section{Reproducibility and Experimental Setup}

This section specifies the evaluation scope, source predictions, primary verifier, and implementation.

\subsection{Data, Predictors, and Evaluation Scope}

Compatibility fitting uses 1,061 training scans. The 117 development scans do not overlap with the training or evaluation scans and are used for model design and selection of relation families. The shared evaluation set contains 157 official 3DSSG validation scans, 548 relation contexts, and 3,972 exact-match ground-truth relations in the support/contact, proximity, and vertical-order families. Evaluation candidates, source relation scores, and verifier-status labels are not used for fitting. The same fitted estimators are applied to all three predictors without predictor-specific refitting.

\paragraph{VL-SAT.}
We rerun the released VL-SAT Mmgnet checkpoint on the official validation scenes with its 160-object and 26-relation ontology. Evaluation disables data augmentation and uses 128 sampled points per object and 256 per union. The adapter applies a sigmoid to each relation logit and exports the scores for all 26 relation predicates for every ordered pair. This produces 957,008 candidates over 36,808 ordered pairs and 548 contexts. We retain the six predicates in the three evaluated families and join each candidate to geometry by its scan, context, subject, and object identifiers.

\paragraph{Open3DSG.}
We train Open3DSG using the official implementation and non-averaged BLIP configuration, and select the checkpoint using training and development losses only. The official preprocessing produces candidates for 533 of the 548 contexts. The evaluation retains all 548 contexts and treats the 15 contexts without candidates as empty sets.

\paragraph{SGFN.}
We evaluate the released SGFN checkpoint with its 160-object and 26-relation configuration on the same validation scenes using the same Recall denominator of 3,972 relations.

\paragraph{Source relation scores.}
The observed proximity and vertical-order score ranges are
\([5.30{\times}10^{-22},0.9954]\) for VL-SAT,
\([0.6394,0.9281]\) for Open3DSG, and
\([4.61{\times}10^{-20},0.5846]\) for SGFN. All evaluated scores are positive, so multiplication by compatibility cannot reverse their order through a sign change. These ranges are observations, not calibrated probability intervals.

For vertical order, \((\delta_z^p,\widetilde\delta_z^p)\) equals \((\Delta z,\Delta z^{\rm norm})\) for \texttt{higher than} and its negation for \texttt{lower than}. \paragraph{Support/contact score.}
For a signed gap \(g\), define
\(\rho(g;a,b)=\operatorname{clip}(1-(|g|-a)/(b-a),0,1)\). For a point count \(n\), define \(\eta(n;c)=\min(n/c,1)\).
We use the soft-support rule for the \texttt{lying on} predicate or when either endpoint is a pillow, cushion, blanket, clothes, or towel. Otherwise, we use the legged floor-support rule when the object is labeled as floor and the rigid-support rule in all remaining cases.
We use the smallest XY-footprint expansion in \(\{0,0.05,0.10,0.20\}\,\mathrm m\) that contains at least 10 support points. Here \(g_{05/95}\) is the subject height at the 5th percentile minus the local support height at the 95th percentile. We define \(g_{01/99}\) in the same way using the 1st and 99th percentiles.
Legged floor support uses
\[
s_{\rm sc}=0.70\,\rho(g_{01/99};0.08,0.18)+0.30\,\eta(n;50),
\]
with the score clipped below at 0.40 because evidence from low height percentiles alone does not declare a violation. Soft support/contact uses
\(s_{\rm sc}=0.55s_{\rm gap}+0.30\eta(n;50)+0.15\).
For a positive gap, \(s_{\rm gap}=\rho(g_{05/95};0.08,0.20)\).
For a negative gap, the score is 1.0 for overlap up to
\(0.15\,\mathrm m\), decreases linearly to 0.55 at \(0.45\,\mathrm m\), and remains 0.55 beyond that value.
Rigid support uses
\[
s_{\rm sc}=0.55\,\rho(g_{\rm plane};0.08,0.22)
+0.35c_{\rm plane}+0.10\,\eta(n;50).
\]
The local plane is the densest \(0.04\,\mathrm m\) height bin within \([-0.25,0.12]\,\mathrm m\) of the subject bottom and within its XY footprint spanning the 5th to 95th percentiles, expanded by \(0.20\,\mathrm m\). We use this local plane only when at least 10 points are assigned to it. The value \(g_{\rm plane}\) is the subject height at the 5th percentile minus the plane height. Its confidence is
\[
\begin{aligned}
c_{\rm plane}={}&0.40\,\eta(n_{\rm in};10)
+0.30\min(r_{\rm in}/0.15,1)\\
&+0.30\,\rho(e_{\rm plane};0.015,0.060),
\end{aligned}
\]
where \(r_{\rm in}\) is the fraction of points assigned to the plane and \(e_{\rm plane}\) is their mean absolute residual. Missing endpoint geometry is uncertain. The verifier does not assign a status to predicates outside the three evaluated families, so they are excluded from the reported Recall and Violation evaluation.

\paragraph{Separation from training construction.}
Table~\ref{tab:counterfactual-rules} defines how training counterfactuals are constructed, whereas Table~\ref{tab:primary-verifier} defines evaluation statuses. The two procedures share some measurements and thresholds, as made explicit in Table~\ref{tab:construct-dependence}, but evaluation candidates and verifier-status labels are not used for fitting.

\subsection{Implementation Details}

All RelCompat3D preprocessing, fitting, and evaluation use a fixed Docker environment based on Python 3.11.9 with NumPy 1.26.4. Re-ranking requires no GPU. Predictor inference runs in separate containers. Compatibility is computed once per candidate and stored before re-ranking.

\subsection{Point- and Mesh-Based Consistency Audit}
The primary verifier and compatibility estimators share some OBB-derived measurements. We therefore construct an alternative audit from reconstructed instance points and meshes. The point-based estimate uses robust distances and heights from reconstructed instance vertices. The mesh-based estimate uses area-weighted samples from reconstructed mesh triangles. A candidate is labeled satisfied or violated only when these estimates agree. A disagreement is labeled uncertain. Thresholds are fixed from training-split positives. Both estimates exclude OBB measurements, source relation scores, learned compatibility, predictor identity, and primary verifier labels. Table~\ref{tab:surface-audit-full} reports the agreement-based Violation values for both estimators at all five $K$ values.

For each estimator, agreement-based Violation is lower than or tied with Source in all 15 predictor--$K$ settings. The only tie is SGFN at $K=5$. The paired 95\% interval is below zero in every setting where the point estimate decreases. Point-only and mesh-only Violation values are also no higher than Source. At $K=50$, 95.5--98.3\% of selected candidates have both point and mesh measurements. Among those candidates, 71.0--85.7\% receive a satisfied or violated label across predictors and estimators.

\paragraph{Robust-density baseline.}
The non-learned robust-density baseline uses only geometric measurements from training-split positive relations. It computes predicate-specific medians and interquartile ranges and uses transformation averaging, the same product score, and the same family-aware re-ranking rule. It does not use verifier labels from the evaluation or constructed counterfactual negatives.
Table~\ref{tab:simple-baseline} reports all $K$ values. At $K=50$, both learned estimators have higher Recall and lower Violation than this baseline for all three predictors. The baseline improves both metrics over a learned estimator only for MLP on Open3DSG at $K=5$; the other comparisons favor a learned estimator on both metrics or show a trade-off.

\paragraph{Compatibility estimators and matched fusion.}
The MLP is a matched nonlinear estimator rather than a separate method. RankAvg and reciprocal rank fusion (RRF) use the Linear compatibility ranks:
\begin{equation}
\begin{aligned}
\mathrm{RankAvg}_i=\tfrac{1}{2}
\left(\widetilde r_i^Z+\widetilde r_i^C\right),\\
\mathrm{RRF}_i=
\frac{1}{60+r_i^Z}+\frac{1}{60+r_i^C}.
\end{aligned}
\end{equation}
Here $r_i^Z$ and $r_i^C$ are within-family ranks, and tildes denote normalized ranks. Main Table~1 reports both fusion rules at every $K$. Their predictor-dependent Recall--Violation trade-offs show that neither RankAvg nor RRF consistently improves both metrics over the product score across predictors and reported $K$ values.

\paragraph{Matched MLP controls.}
Table~\ref{tab:ablations-k50} reports the matched controls for the MLP estimator. Main Table~2 reports the corresponding Linear controls. Across both reported $K$ values and both compatibility estimators, using incorrect predicates or mismatched ordered-pair measurements increases verifier-derived Violation. Compatibility-only ordering remains close to the full estimator on Open3DSG but loses substantial Recall on VL-SAT and SGFN. These controls support the predictor-dependent role of the source relation score described in the main paper.

\paragraph{Matched routing controls.}
The \emph{family-aware} rule preserves the source relation-family label at every rank position. It re-ranks proximity and vertical-order candidates in separate family lists. The matched \emph{joint P/V} control uses the same candidates, compatibility estimates, product scores, and support/contact positions and identities. It differs only by placing proximity and vertical-order candidates in one list. Table~\ref{tab:routing-constraint} reports this comparison at all five $K$ values.

No rule is best in every setting. For Open3DSG, Joint P/V raises Linear Recall at all five $K$ values. For the MLP, it raises Recall at $K=5,10$ but lowers it at $K=50,100$. The paired Recall intervals for both decreases are below zero. At Open3DSG $K=50$, the MLP control changes the selected proximity/vertical-order counts from 6,295/6,508 to 3,423/9,380 while leaving all 13,833 support/contact selections unchanged. We therefore interpret family-aware re-ranking as a constraint that preserves relation-family composition, not as a rule that maximizes aggregate performance.

\paragraph{Additional robustness checks.}
These checks do not change the main comparisons or broaden the claim beyond the shared 3DSSG validation scenes. We repeat training with five pre-specified seeds.
