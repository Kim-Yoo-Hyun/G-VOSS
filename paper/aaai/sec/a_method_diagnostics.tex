\section{Guarantees and Compatibility Analyses}

\begin{proposition}[Exact transformation consistency]
Let a finite transformation group $H_a$ act jointly on the predicate and
geometry of an ordered pair, and define
$C_a^{\rm tr}(x)=|H_a|^{-1}\sum_{g\in H_a}C_a(gx)$. Then
$C_a^{\rm tr}(hx)=C_a^{\rm tr}(x)$ for every $h\in H_a$.
\end{proposition}

\paragraph{Proof.}
For any $h\in H_a$,
\(
C_a^{\rm tr}(hx)=|H_a|^{-1}\sum_{g\in H_a}C_a(ghx)
\).
Right multiplication by $h$ is a bijection on the finite group, so re-indexing
$g'=gh$ gives $C_a^{\rm tr}(hx)=C_a^{\rm tr}(x)$. The two-element proximity
and vertical actions yield the identities in the main paper, and the singleton
support/contact action is the identity.

\paragraph{Family-sequence preservation.}
For each family $a$, the algorithm constructs the ordered list $\pi_a$ defined
in the main paper. At position $j$, it selects the next unselected candidate
from $\pi_{a_j}$; hence the output family sequence is exactly
$(a_1,\ldots,a_n)$. The support/contact list follows the source ranking, so the
first $K$ positions contain exactly the same ordered support/contact subsequence
as the source prefix. Therefore the support/contact selections and their order
are identical at every reported $K$.

\paragraph{Prefix utility optimality.}
Fix a prefix length $K$, and let $n_a(K)$ be the number of positions assigned
to family $a$ in the source prefix. Every feasible ranking that preserves these
family counts must select $n_a(K)$ candidates from each family. Because each
re-ranked $\pi_a$ is sorted by its variant's $u_i$, either \method{} estimator selects the $n_a(K)$
highest-utility candidates within that family. If another feasible selection
omits one of these candidates in favor of a lower-utility candidate from the
same family, exchanging the two increases the summed within-prefix utility.
The support/contact subsequence is fixed, so it does not affect this comparison.

\paragraph{Counterfactual target construction.}
Measured-family ground-truth relations provide positives. Negatives are generated
within the same scene context and linked to their source positive; no predictor
score, predictor identity, or evaluation candidate is used.
Table~\ref{tab:counterfactual-rules} gives the complete construction policy.

At most two negatives are emitted per positive, 200 per context--family, and
three times the number of positives per family. These caps limit repeated easy
negatives; they do not equalize family counts. The export contains 28,977
positives and 37,477 negatives. Total rows by family are 23,008 proximity,
5,488 vertical, and 37,958 support/contact. The explicit overlap above is why
Violation computed by the rule-based geometry verifier is reported as a
verifier-derived measure rather than independent physical-validity ground truth;
the feature-removal analysis tests, but does not eliminate, this construct
dependence.

\methodlinear{} fits one logistic model per measured relation family. Numeric
features use means and standard deviations estimated from the training split;
missing values use the corresponding training mean. Inputs are predicate
indicators $T$, predicate-independent geometric measurements of the ordered pair $G$, and the
two predicate-signed height interactions defined in the main paper. The
family label selects the head and is not repeated as an input. The predictor
score, source rank, predictor identity, and object class are excluded.
Transformation-consistent augmentation preserves the proximity predicate
under endpoint swap; vertical order swaps endpoints and applies the inverse
predicate. Linked counterfactuals receive the fixed margin loss in the main
paper. Support/contact receives the pairwise loss but no blanket endpoint
transform.

\methodmlp{} fits a single shared two-hidden-unit ReLU model with a
predicate-linear skip connection. Its 29 inputs comprise family and predicate
indicators, the same 17 geometric measurements, the two signed-height
interactions, and the sum of the directional overlap ratios. The family
indicator is nonconstant because this estimator shares parameters across
families. It has 69 parameters and excludes the predictor score and identity.

The 60,208 training rows yield 33,961 linked pairs, and
transformation-consistent augmentation produces 86,032 optimization rows for
both estimators. Linear uses 800 deterministic full-batch steps at learning rate
0.2; MLP uses 120 steps at learning rate 0.02. Both use the same pairwise
weight, margin, $\ell_2$ coefficient, and fixed seed policy. The three linear
family models contain 21--23 parameters. The support/contact head is retained
for the Product (all families) comparison, while neither proposed ranking uses
support/contact compatibility and both preserve that family's source ordering.

\paragraph{Computational cost.}
We benchmark the fixed \methodlinear{} CPU implementation with one process and one thread on
an Intel Core Ultra 7 265KF. Timing begins from preloaded relation candidates with
precomputed geometric measurements of the ordered pair and includes proximity/vertical compatibility,
transformation averaging, family-specific list sorting, and output assembly. It excludes
source-predictor inference, reconstruction and geometry association, file parsing, metrics,
and bootstrap, so it is not end-to-end pipeline latency. Table~\ref{tab:runtime}
