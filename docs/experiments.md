# Experiment Workflow

Last updated: 2026-05-28

This document is the workflow rulebook for Docker-based paper experiments. It
does not replace `docs/reproducibility.md`, which owns recovery commands,
artifact transfer, model/data locations, and cleanup safety. It also does not
replace `experiments/**/README.md`, which owns experiment-local status,
outputs, and run records.

## Ownership

- `docs/experiments.md`: experiment workflow rules, promotion gates, source
  adapter expectations, metric-freeze requirements, and paper-result boundary.
- `experiments/<experiment>/README.md`: local entry point, current status,
  source-specific outputs, blockers, and next commands.
- `experiments/<experiment>/commands.md`: concise reproducible command index.
- `experiments/<experiment>/compose*.yaml`: Docker services that produce
  paper-facing artifacts.
- `experiments/<experiment>/scripts/`: executable experiment logic.
- `docs/reproducibility.md`: dataset/checkpoint/cache paths, artifact bundles,
  recovery order, transfer guidance, and long-running command templates.

## Root Creation Rule

When a new durable root-level research/workflow folder is created or activated,
the agent must create or update the corresponding `docs/<folder>.md` file before
substantive work begins in that root. The new docs file should define:

- the folder's responsibility,
- the local README/report ownership pattern,
- what counts as paper-result evidence,
- what must stay as smoke/preflight evidence,
- how Docker, logs, manifests, and ignored local data are handled.

After adding the docs file, update `docs/index.md`, `AGENTS.md`, and the
relevant README role map with a pointer. This rule is for durable workflow roots
such as `experiments/`, `paper/`, `literature/`, and `hypothesis/`; it does not
apply to ignored or transient roots such as `logs/`, `local_dataset/`, or
`release/`.

## Paper-Result Promotion

An output may be treated as paper experiment evidence only if:

- it was generated by a Docker service or a documented Docker-compatible
  background job,
- the input paths, output paths, command, and expected files are recorded,
- the output has a manifest with schema/status, input provenance, output list,
  blockers/warnings, and claim boundary,
- JSON/JSONL validation or a lightweight sanity check passed,
- source-specific caveats are reported rather than hidden,
- `TODO.md` and the closest experiment README were updated.

Host-only scripts may be used for planning, inspection, or document hygiene, but
host-only outputs must not be promoted to paper metrics.

## Source Adapter Rule

Every semantic source must be converted into a row-level prediction contract
before metric evaluation. The contract must preserve:

- `source_name` and `baseline_run_id`,
- scan/subgraph identity,
- subject/object ids and labels,
- predicate family and exact predicate label,
- semantic score or ranking score,
- deterministic prediction id or resume key.

Geometry joins, verifier/calibrator outputs, and metric rows must be keyed by
the same identity fields. Any missing context, filtered split, or unsupported
relation family must be reported as a denominator caveat.

## Metric Freeze Rule

Before running a new source metric or relation-family metric, freeze a protocol
artifact that specifies:

- source rows and exact-label GT denominator,
- source-specific coverage denominator,
- scoring output schema,
- ranking conditions,
- control order,
- bootstrap/audit requirements if the result will affect paper claims,
- known caveats such as missing dev labels, unsupported contexts, or residual
  calibration risk.

Metric freeze artifacts are not themselves metric evidence. They are promotion
guards that prevent metric-dependent threshold tuning.
